## 0. Project at a Glance

**Product:** HapticWay — offline-first mobile navigation app for visually impaired students. Detects obstacles via on-device computer vision and signals proximity through a vibration-based "Haptic Radar."

**Core thesis:** Cloud-based vision aids fail safety-critically because round-trip latency (466ms–2000ms) exceeds the time a walking user has to react. HapticWay solves this by running all inference on-device, with zero network calls in the navigation loop.

**Target platform:** Android first (Android 10 / API 29+, ARCore-supported devices). iOS is Phase 5 stretch.

**Starting state:** Empty repo. This todo includes scaffolding from `flutter create`.

## 1. Hard Constraints (Acceptance Gates)

Every milestone is judged against these. If a task breaks one of these, it is not done.

| # | Constraint | Measured how |
|---|---|---|
| C1 | End-to-end inference latency **P95 < 50 ms** on target device | Per-frame timer logged to JSONL, post-run analysis on ≥20 runs |
| C2 | Object detection accuracy **≥ 85%** on the 8-class obstacle set | Confusion matrix over labelled test set; mean + SD reported |
| C3 | False-positive rate characterised separately from false-negative rate | Both reported in benchmark summary; FP rate must not "train out" trust |
| C4 | **No network calls in the navigation loop.** Detection, depth, haptic feedback all run offline | Lint rule + integration test asserts no `dart:io` HTTP usage on the inference path |
| C5 | **Camera frames are never persisted.** Each frame discarded within the inference cycle | Code review; static check that no `File.writeAsBytes` runs in the camera pipeline |
| C6 | WCAG 2.1 Level AA across POUR | Automated audit + manual TalkBack pass per screen |
| C7 | Manual override exists to disable haptic alerts (UK GDPR Art. 22) | Settings toggle, surfaces on home screen long-press |
| C8 | App functions in network dead zones (basements, lifts) | Airplane-mode integration test; full nav loop must pass |

**Model:** SSD MobileNet v2 320×320, fine-tuned on the 8-class HapticWay obstacle set, then post-training-quantized to INT8. Base weights from TensorFlow Object Detection Model Zoo (Apache 2.0, attribution required). Custom training pipeline in §5.6.

**Native code:** Kotlin for Android platform channels (vibration motor, ARCore depth buffer access).

### 6.2 Inverse-square haptic mapping (Week 12)
- [ ] `lib/haptics/intensity_curve.dart`:
  ```dart
  // A(d) = min(1.0, k/d²)
  double amplitudeFor(double distanceMeters, {required double k}) {
    if (distanceMeters <= 0) return 1.0;
    return math.min(1.0, k / (distanceMeters * distanceMeters));
  }
  ```
- [ ] `lib/haptics/haptic_engine.dart`:
  - Subscribe to `(Detection, distance) → amplitude` stream
  - Call native vibration channel with amplitude ∈ [0, 1] mapped to motor's 0–255 range

- [ ] `lib/haptics/tacton.dart` — pattern library: `obstacleAhead`, `obstacleLeft`, `obstacleRight`, `manualOverrideOn`, `manualOverrideOff`
- [ ] `android/app/src/main/kotlin/com/hapticway/HapticChannel.kt`:

- [ ] Acceptance: walk toward a wall — vibration ramps smoothly from imperceptible (4 m) to maximum (< 0.7 m); ramp curve is non-linear and matches `A(d) = min(1.0, k/d²)` within 5%

## 8. Cross-Cutting Concerns (apply throughout)

### 8.1 Privacy & data minimisation (UK GDPR Art. 5(1)(c), 25)
- [ ] Code review checklist: every PR that touches `lib/inference/` confirms no frame persistence, no network call
- [ ] No analytics SDKs of any kind
- [ ] `shared_preferences` stores only: sensitivity `k` value, override toggle state, onboarding-complete flag
- [ ] No user identifier is ever generated or stored

### 8.2 Security (BCS Code of Conduct, NCSC supply chain)
- [ ] Pin every dependency exactly in `pubspec.yaml` (no `^` for production lockdown; use `^` during dev, lock before release)
- [ ] Run `flutter pub deps --json` weekly; flag any new transitive dependency
- [ ] Sign release APK with a key stored outside the repo
- [ ] Do not request `INTERNET` permission in the production manifest

### 8.3 Accessibility (WCAG 2.1 AA — POUR)
- [ ] Perceivable: every non-decorative widget has `Semantics(label: ...)`; contrast ratio ≥ 7:1
- [ ] Operable: every action accessible via touch + screen reader gesture; no time-limited interactions; touch targets ≥ 48 dp
- [ ] Understandable: linear focus order; consistent navigation; error messages name the field and the fix
- [ ] Robust: only standard widgets — no custom-painted elements without explicit Semantics

### 8.4 Safety (Health & Safety at Work Act 1974)
- [ ] App displays a "Safety Notice" on first launch: "HapticWay is an aid, not a replacement for cane or guide dog." User must acknowledge.
- [ ] Manual override is reachable from any screen via a 2-finger long press
- [ ] If inference fails > 3 consecutive frames, app announces "Detection unavailable — use primary mobility aid"

### 8.5 Logging hygiene
- [ ] All debug logs gated behind `kDebugMode`
- [ ] Benchmark logs contain no images, no audio, no participant identifiers — only timing + class labels + bbox geometry
- [ ] Logs auto-purge after 7 days
